# BPMN Studio — локальный ассистент (Local API)

Небольшой сервер на вашем компьютере. Он отвечает в формате **OpenAI Chat Completions**, а ответы получает от установленного у вас **Claude Code CLI** (`claude -p`) по вашей подписке Claude, без API-ключа. BPMN Studio в браузере подключается к нему в режиме **Local API**.

## Установка

1. Нужны **Node.js 18+** и **Claude Code**, в который вы вошли:
   ```bash
   npm install -g @anthropic-ai/claude-code
   claude login
   ```
2. Распакуйте архив и запустите сервер:
   ```bash
   cd bpmn-studio-local
   node server.js
   ```
   В Windows можно дважды щёлкнуть `start.cmd`, в macOS/Linux — запустить `./start.sh`.
3. В BPMN Studio откройте **Ассистент → ⚙ Настройки → Local API** и нажмите **«Проверить соединение»**.

Архив, скачанный из студии, уже настроен: в `config.json` записаны адрес студии и личный токен. Тот же токен сохранён в настройках студии в вашем браузере.

## config.json

| Поле | По умолчанию | Описание |
|---|---|---|
| `port` | `8138` | Порт |
| `host` | `127.0.0.1` | Адрес. Любой не-loopback адрес требует `token`, иначе сервер не запустится |
| `token` | — | Если задан (не короче 16 символов), запросы должны идти с `Authorization: Bearer <token>` |
| `allowedOrigins` | `["*"]` в скачанном архиве | С токеном сервер принимает запросы с любого адреса студии (GitHub Pages, свой домен, localhost) — без токена их всё равно не выполнить. Без токена — только localhost и перечисленные адреса; `"*"` без токена не допускается |
| `defaultModel` | `opus` | Модель Claude Code, если клиент её не указал (`opus`, `sonnet`, `haiku`) |
| `timeoutMs` | `1800000` | Максимальная длительность одного ответа |
| `maxConcurrent` | `2` | Сколько процессов `claude` одновременно; лишние запросы получают 429 |
| `claudeBin` | `claude` | Путь к Claude Code CLI |

Переменные окружения `BPMN_LOCAL_PORT`, `BPMN_LOCAL_HOST`, `BPMN_LOCAL_TOKEN`, `BPMN_LOCAL_ALLOWED_ORIGINS`, `BPMN_LOCAL_TIMEOUT_MS`, `BPMN_LOCAL_MAX_CONCURRENT`, `CLAUDE_BIN` переопределяют этот файл. Ошибки в конфиге (не JSON, неверный порт и т. п.) останавливают запуск с понятным сообщением.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | Статус, версия, установлен ли `claude` (`?refresh` — проверить заново) |
| GET | `/v1/models` | `opus`, `sonnet`, `haiku` |
| POST | `/v1/chat/completions` | OpenAI-совместимый, со стримингом (`"stream": true`) и вызовом функций (`"tools"`) |

```bash
curl http://127.0.0.1:8138/v1/chat/completions \
  -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  -d '{"model":"sonnet","messages":[{"role":"user","content":"Привет"}]}'
```

С этим сервером работает любой клиент OpenAI SDK: `base_url = http://127.0.0.1:8138/v1`, `api_key = <token>`.

### Вызов функций (tools)

Если в запросе есть `tools`, Claude отвечает через `--json-schema` строго в формате `{message, tool_calls[]}`. Сервер превращает этот ответ в стандартные OpenAI `tool_calls` (`finish_reason: "tool_calls"`). Результаты передаются обратно сообщениями `role: "tool"`, как в OpenAI. Сами инструменты выполняет **клиент** (BPMN Studio), а не Claude Code.

## Безопасность

- **Только текст.** Каждый запуск `claude` получает `--tools "" --strict-mcp-config --no-session-persistence --disable-slash-commands` и свою пустую временную папку, которая удаляется после ответа. Claude не может запускать команды, читать ваши файлы, использовать ваши MCP-серверы или выполнять slash-команды (текст пользователя всегда передаётся как реплика `User: …`). Сессии не попадают в историю Claude Code.
- Системный промпт передаётся файлом (`--system-prompt-file`), а не в командной строке: вместе со списком инструментов он больше 32 КБ — предела командной строки Windows. В Windows сервер запускает `claude.exe` или `cli.js` из npm-установки напрямую, без `cmd.exe`.
- **Доступ из браузера.** С токеном — с любого адреса студии: каждый запрос должен нести `Authorization: Bearer <token>`, иначе 401. Без токена — только localhost и `allowedOrigins`, остальные получают 403. Сервер отдаёт заголовки CORS и `Access-Control-Allow-Private-Network` (иначе Chrome не пускает страницу из интернета на `127.0.0.1`); в новых версиях Chrome ещё спрашивает разрешение «доступ к устройствам в локальной сети» — его нужно дать.
- **Токен** (`Authorization: Bearer`) и проверка `Host` (защита от DNS rebinding).
- По умолчанию слушает только `127.0.0.1`. Не открывайте сервер в сеть: он расходует лимиты вашей подписки Claude (без токена на внешнем адресе он и не запустится).

## Ограничения

- `temperature`, `max_tokens` и подобные параметры принимаются, но CLI их не поддерживает.
- Только текст: сообщения с картинками и другими не-текстовыми частями получают 400 (а не молча теряют картинку).
- Чанк с расходом токенов в стриме приходит, только если клиент попросил: `"stream_options": {"include_usage": true}`.
- Когда есть `tools`, ответ не стримится по токенам: он приходит одним куском после генерации. Это ограничение структурированного вывода CLI.
- Каждый запрос запускает новый процесс `claude`; историю диалога присылает клиент.
