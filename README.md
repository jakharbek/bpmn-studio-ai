# BPMN Studio

Веб-редактор BPMN на bpmn.io со встроенным ИИ-ассистентом. Вы описываете процесс словами, ассистент строит диаграмму, и она сразу появляется в редакторе, где её можно править мышкой.

**Всё работает в браузере.** Сервера с данными нет: студия — набор статических файлов (`dist/site`), её можно положить на любой хостинг (nginx, S3, GitHub Pages) или открыть локально. Диаграммы хранятся в браузере пользователя (IndexedDB), ассистент и его инструменты работают там же, «Отправить схему» идёт из браузера напрямую на ваш сервер.

```bash
./run.sh setup
```

```bash
./run.sh start
```

Откройте http://127.0.0.1:3333.

## Запуск и остановка: `run.sh`

| Команда | Что делает |
|---|---|
| `./run.sh start` | Запустить в фоне. Если исходники новее сборки — сначала пересобирает сайт. Ждёт, пока сервер ответит |
| `./run.sh stop` | Остановить (SIGTERM, через 10 с — SIGKILL) |
| `./run.sh restart` | Перезапустить на том же адресе (с пересборкой, если нужно) |
| `./run.sh status` | PID, адрес, время работы, отвечает ли, актуальна ли сборка. Код выхода: 0 — работает, 1 — упал, 3 — не запущен |
| `./run.sh logs [N\|-f]` | Последние N строк журнала или следить за ним |
| `./run.sh open` | Открыть студию в браузере |
| `./run.sh run` | Запустить в текущем терминале (Ctrl+C — остановить) |
| `./run.sh build` / `setup` / `test` / `doctor` | Собрать сайт / установить зависимости и собрать / тесты / проверить окружение |

Настройки — переменными окружения: `PORT` (3333), `HOST` (`127.0.0.1`; `0.0.0.0` — доступ из локальной сети), `FORCE_BUILD=1`, `NO_BUILD=1`, `START_TIMEOUT`, `STOP_TIMEOUT`, `BPMN_RUN_DIR`. Пример: `PORT=8080 HOST=0.0.0.0 ./run.sh restart`.

- PID и журнал лежат в `.run/`; журнал ротируется при 10 МБ.
- Одновременные команды из разных терминалов не мешают друг другу (блокировка): два `start` дают один сервер.
- PID записывает сам сервер после того, как начал слушать порт, и сверяется с командной строкой процесса — чужой процесс с тем же PID не будет остановлен по ошибке.
- Если порт занят, `start` скажет, каким процессом. После аварийного завершения `status` это покажет, а `start` запустит заново.
- Сервер отдаёт только статические файлы: схем на нём нет, поэтому `stop`/`restart` ничего не теряют.

## Где хранятся схемы

- В **IndexedDB этого браузера на этом компьютере**. Другой браузер или компьютер видит свой, отдельный набор схем.
- Вкладки одного браузера синхронизируются сразу (`BroadcastChannel`): правка в одной вкладке появляется в другой.
- Студия просит браузер не удалять данные при нехватке места (`navigator.storage.persist()`), но очистка данных сайта вручную их удалит. Поэтому есть **резервная копия**:
  - **Скачать ▾ → Все схемы (.zip)** — архив со всеми схемами;
  - **Открыть файл** (или перетаскивание на окно) принимает `.bpmn`, `.xml` и такой `.zip`. Существующие схемы не перезаписываются без подтверждения.
- У каждой схемы до 50 предыдущих версий: ассистент может отменить (`bpmn_undo`) и вернуть (`bpmn_redo`) изменение, ничего не теряя.
- **Переименовать** меняет имя схемы. Содержимое, id процесса (ключ деплоя в движке) и история отмен сохраняются; несохранённые правки сначала сохраняются под старым именем и переезжают вместе со схемой. Другие открытые вкладки сразу переключаются на новое имя. Можно попросить и ассистента: «переименуй схему в order-v2».
- **Удалить** убирает схему из браузера (без возможности восстановления — сначала сделайте копию).

## Ассистент: 5 способов подключения

Ассистент настраивается в **чате → ⚙ (Настройки ассистента)**:

| Режим | Как работает | Что нужно |
|---|---|---|
| **OpenAI API** | Chat Completions + function calling | API-ключ OpenAI |
| **Claude API** | Anthropic Messages API через официальный SDK (`@anthropic-ai/sdk`), по умолчанию `claude-opus-5-5` с серверным fallback | API-ключ Anthropic |
| **OpenRouter API** | OpenAI-совместимый API, сотни моделей | API-ключ OpenRouter |
| **Local API** | Скачиваемый локальный сервер → Claude Code CLI на компьютере пользователя | подписка Claude (`claude login`), Node.js 18+ |
| **Custom LLM Provider** | Любой OpenAI-совместимый API: Qwen, DeepSeek, Mistral, Groq, Ollama, LM Studio, корпоративный шлюз | Base URL, модель; ключ — если сервис требует |

- Запросы к модели идут **напрямую из браузера**. Ключи хранятся только в этом браузере (`localStorage`) и отправляются только выбранному провайдеру.
- Инструменты ассистента выполняются в браузере и работают только со схемами этого браузера.
- «Отправить схему» по просьбе ассистента выполняется только после подтверждения пользователя.
- Ответы модели показываются как Markdown без картинок и встраиваемого содержимого (через них можно было бы вывести данные на чужой сервер), ссылки открываются в новой вкладке.
- **«Проверить соединение»** загружает список моделей. Для Local API проверяется ещё и наличие Claude Code.

### Custom LLM Provider

Пресеты заполняют Base URL; ключ и модель указываете сами, модели загружаются кнопкой «Проверить соединение».

| Пресет | Base URL |
|---|---|
| DeepSeek | `https://api.deepseek.com` |
| Qwen (Alibaba Cloud, international) | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` |
| Qwen (Alibaba Cloud, China) | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| Mistral | `https://api.mistral.ai/v1` |
| Groq | `https://api.groq.com/openai/v1` |
| Ollama (на компьютере пользователя) | `http://127.0.0.1:11434/v1` — запустите с `OLLAMA_ORIGINS=<адрес студии>` |
| LM Studio (на компьютере пользователя) | `http://127.0.0.1:1234/v1` — включите CORS в настройках сервера |
| Другой | любой адрес, к которому добавляются `/chat/completions` и `/models` |

- Модель должна поддерживать **вызов функций (tools)**.
- Если сервис не отдаёт `/models`, проверка соединения делает минимальный запрос к модели (`max_tokens: 1`).
- В «Дополнительно» — дополнительные заголовки (JSON-объект со строковыми значениями). Ключ из поля «API-ключ» имеет приоритет.
- Сервис должен разрешать CORS (DeepSeek и Qwen разрешают). Иначе студия покажет понятную ошибку.

### Local API: локальный сервер

1. **Local API → «Скачать сервер (.zip)»**. Архив собирается в браузере и уже настроен: в `config.json` личный токен (он же сохранён в браузере). С токеном сервер принимает запросы с любого адреса студии — один и тот же архив работает и с GitHub Pages, и с локальной студией.
2. Распакуйте и запустите `node server.js` (или `start.cmd` / `start.sh`).
3. **«Проверить соединение»**.

Сервер (`local-server/`, без зависимостей) — OpenAI-совместимый `/v1/chat/completions` поверх `claude -p`. Вызовы функций эмулируются через `--json-schema`; сам Claude Code запускается без инструментов, MCP и slash-команд, в пустой временной папке. Подробности — [local-server/README.md](local-server/README.md).

## Классический редактор Camunda 7

Диаграммы Camunda 7 открываются в классическом редакторе bpmn.io для Camunda 7:

- bpmn-js **7.4.0**, bpmn-js-properties-panel **0.42.0**, camunda-bpmn-moddle **5.1.2**, diagram-js 6.8.2, bpmn-moddle 7.1.2;
- версии остальных зависимостей закреплены (moddle 5.0.2, moddle-xml 9.0.5, ids 1.0.0, min-dom 3.1.3, diagram-js-direct-editing 1.6.3 …); `lodash`, `semver` и `min-dash` — на патч-версиях без известных уязвимостей;
- стандартная сборка: `propertiesPanelModule` + `provider/camunda` + `camunda.json`, стили bpmn-js и панели свойств.

Палитра, контекстное меню и вкладки панели (General, Forms → Form Key / **Form Fields (Generated Task Forms)**, Listeners, Input/Output, Field Injections, Extensions) — те же самые. Исходники сборки — `web/legacy/` (отдельный `package.json` с точными версиями).

Современный редактор camunda-bpmn-js для Camunda 7: `"camunda7Editor": "modern"` в `bpmn-studio.config.json`. Диаграммы Camunda 8 всегда открываются в camunda-bpmn-js.

Ассистент умеет Generated Task Forms и при любой правке **сохраняет то, что не описывает его модель**: listeners, Input/Output, async before/after, job priority, field injections, properties, version tag, history time to live, скриптовые условия.

## Платформа и отправка схемы

[`bpmn-studio.config.json`](bpmn-studio.config.json) лежит рядом с сайтом и читается при загрузке страницы:

```json
{
  "defaultPlatform": "camunda7",
  "camunda7Version": "7.24.0",
  "deploy": {
    "path": "/api/bpmn/deploy",
    "field": "bpmnBase64",
    "targets": { "dev": "https://dev.example.com", "prod": "https://prod.example.com" }
  }
}
```

- `camunda7Version` — версия движка: от неё зависят набор правил проверки и атрибуты новых схем;
- `deploy.path` и `deploy.field` — адрес и имя поля API вашего сервера, принимающего схему;
- `deploy.targets` — серверы в меню «Отправить схему».

- **Camunda 7 по умолчанию**: новые диаграммы и ассистент создают Camunda 7 (JUEL `${…}`, external task / delegate expression / class). Camunda 8 — по просьбе.
- **«Отправить схему ▾»**: `POST {сервер}{deploy.path}` с телом `{"<deploy.field>": "<base64 XML>"}`. Сервер из списка или «Другой адрес…». При ошибках деплоя студия покажет их и спросит, отправлять ли всё равно.
- Запрос идёт **из браузера**, поэтому бэкенд должен разрешать CORS для адреса студии (`Access-Control-Allow-Origin`, метод `POST`, заголовок `Content-Type`). Если студия открыта по `https://`, а сервер по `http://`, браузер заблокирует запрос (mixed content) — откройте студию по `http://` или включите HTTPS на сервере.
- В чате: «отправь схему на dev». Ассистент отправляет только по прямой просьбе, на названный сервер и после вашего подтверждения.

Проверка для Camunda 7: правила `camunda-compat` (наборы есть с 7.19; более ранняя версия проверяется по ближайшему набору) плюс собственные проверки того, что движок Camunda 7 отклоняет при деплое (сервис-задача без реализации, скрипт без формата, call activity без `calledElement`, таймер без значения, сообщение/ошибка без имени и кода, неисполняемый процесс).

## Что умеет

**Редактор** (слева):
- Палитра, контекстные меню, панель свойств Camunda 8 / Camunda 7. Платформа определяется по файлу, редактор переключается сам.
- Автосохранение через ~0,6 с после правки; Ctrl+S — сохранить сразу.
- Панель «Проблемы»: правила Camunda Modeler (`camunda-compat` + `bpmnlint`), подсветка элементов, клик — выделить элемент.
- Скачать .bpmn, .svg или все схемы (.zip).

**Работа ассистента видна по ходу** (всё приходит потоком):
- живая строка состояния с таймером: «Отправил запрос, жду ответ модели» → «Думает» → «Готовит действие «Создаю диаграмму» · 2,3 тыс. символов» → «Выполняет «Проверяю диаграмму»» → «Пишет ответ», с номером шага;
- если модель молчит дольше 20 с, строка желтеет и объясняет, что модель ещё работает и что «Стоп» прервёт — так видно, что ничего не зависло;
- размышления модели — потоком в сворачиваемом блоке (Claude API: краткий пересказ размышлений, `display: "summarized"`; DeepSeek/Qwen: `reasoning_content`; OpenRouter: `reasoning`; Local API: размышления Claude Code);
- каждое действие — карточка со статусом и временем; по клику раскрываются аргументы и результат;
- под ответом: общее время, число шагов и действий, токены.

Local API тоже стримит: пока Claude Code готовит структурированный ответ с действиями, сервер пересылает его размышления и прогресс, а раз в 15 с — сигнал «жив».

История чата хранится в IndexedDB целиком: Claude проверяет, что прошлые ходы не изменены, и сокращённая история стоила бы ему размышлений. Если такая проверка всё же не прошла (ошибка 400), прежние размышления отбрасываются и запрос повторяется один раз.

**Чат** (справа):
- Ассистент видит, какая схема открыта и что выделено: «переименуй выделенное», «добавь шаг после этого».
- Изменения появляются в редакторе сразу, с сохранением масштаба. Если меняются только названия и свойства, ваша раскладка сохраняется.
- Если вы правили схему, пока её менял ассистент (или другая вкладка), автосохранение останавливается и появляется выбор: «Загрузить» их версию или «Оставить мою». Без выбора ничего не перезаписывается; при переходе на другую схему студия спросит, терять ли правки.
- **Пулы и дорожки**: «разложи по ролям: менеджер, бухгалтерия, склад», «клиент и банк — внешние участники», «перенеси проверку в дорожку Риски».

```
┌───────────────────────────────────────────────────────┐
│ app.js     редактор bpmn-js, чат, настройки           │
│ core.js    хранилище (IndexedDB) · инструменты bpmn_*  │
│            · lint · раскладка · zip · ядро ассистента  │
└──────┬──────────────────────┬─────────────────────────┘
       │ модель               │ «Отправить схему»
       ├─► api.openai.com / api.anthropic.com / openrouter.ai / свой
       ├─► http://127.0.0.1:8138  (Local API → claude -p)

```

| Путь | Что это |
|---|---|
| `src/` | Изоморфное ядро: генерация и правка BPMN, раскладка, линтер, хранилище, инструменты ассистента |
| `web/assistant/` | Провайдеры моделей и цикл ассистента; `core.js` — точка входа бандла `BpmnCore` |
| `web/public/` | Страница: `index.html`, `app.js`, `app.css` |
| `web/legacy/` | Сборка классического редактора Camunda 7 (bpmn-js 7.4) |
| `local-server/` | Скачиваемый сервер Local API |
| `scripts/build-site.mjs` | Сборка `dist/site` |
| `scripts/serve.mjs` | Статический сервер для разработки (только `127.0.0.1`) |

## Сборка и публикация

```bash
npm run build
```

Результат — `dist/site` (~9 МБ). Скопируйте папку на любой статический хостинг; пути относительные, сайт работает и из подпапки. Правьте `bpmn-studio.config.json` прямо в опубликованной папке, пересборка не нужна.

## Публикация на GitHub Pages

В репозитории есть workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml): при каждом push в `master` он устанавливает зависимости, собирает сайт, проверяет, что в опубликованном конфиге нет адресов внутренней сети, прогоняет тесты и публикует `dist/site`.

1. Создайте репозиторий на GitHub и отправьте туда проект (`git init`, `git add .`, `git commit`, `git push`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. После первого push сайт появится по адресу `https://<имя>.github.io/<репозиторий>/` (адрес — в отчёте workflow).

**Конфиги:**
- `bpmn-studio.config.public.json` — публикуется: без серверов, нейтральные значения. В студии всегда есть «Другой адрес…».
- `bpmn-studio.config.json` — локальный, со своими серверами и API. Он в `.gitignore` и в репозиторий не попадает; локальная сборка (`./run.sh`) берёт его, если он есть. Другой конфиг для сборки: `STUDIO_CONFIG=имя-файла.json npm run build`.
- `backup/` тоже в `.gitignore`.

**Что учесть на GitHub Pages:**
- Сайт открывается по `https`, поэтому «Отправить схему» на серверы по `http://` во внутренней сети браузер заблокирует (mixed content). Работают `https`-серверы с CORS и `http://localhost`. Для отправки на внутренние dev/prod открывайте студию у себя: `./run.sh start` или `HOST=0.0.0.0 ./run.sh start` на сервере в сети.
- Все проекты одного аккаунта на `<имя>.github.io` — один источник (origin): другие ваши страницы там же могут прочитать ключи ассистента и схемы, сохранённые в браузере. Для студии лучше свой домен (Settings → Pages → Custom domain) или отдельная организация.
- Local API, Ollama и облачные провайдеры работают. Local API: скачайте сервер на этой странице (или вставьте токен сервера в поле «API-ключ»); Chrome может спросить разрешение на доступ к устройствам в локальной сети — его нужно дать.

## Инструменты ассистента

| Инструмент | Что делает |
|---|---|
| `bpmn_create` | Создать диаграмму из элементов и потоков (авто-раскладка), с пулом, дорожками, внешними участниками и потоками сообщений |
| `bpmn_read` | Прочитать схему в редактируемый JSON |
| `bpmn_edit` | Добавить / изменить / переименовать / удалить элементы и потоки, вставить шаг между двумя, менять дорожки и пулы |
| `bpmn_lint` | Проверить правилами Modeler |
| `bpmn_undo`, `bpmn_redo` | Отменить и вернуть изменение |
| `bpmn_rename` | Переименовать схему (имя в студии; название процесса меняет `bpmn_edit processName`) |
| `bpmn_list`, `bpmn_open`, `bpmn_get_xml` | Список, показать в редакторе, получить XML |
| `bpmn_deploy` | Отправить схему на сервер из `bpmn-studio.config.json` (после подтверждения) |
| `bpmn_write_xml` | Сохранить «сырой» XML (вложенные дорожки, несколько развёрнутых пулов, аннотации) |

Каждая запись возвращает `deployErrors` и `modelingIssues`; ассистент исправляет их до ответа. Если пользователь изменил схему, пока ассистент её правил, `bpmn_edit` не перезаписывает, а просит перечитать.

## Ограничения

- Схемы привязаны к браузеру: общего хранилища для команды нет. Обмен — через .zip/.bpmn или «Отправить схему».
- Модель пулов: один исполняемый процесс (в пуле, с дорожками) плюс свёрнутые внешние участники. Вложенные дорожки, несколько развёрнутых пулов, аннотации и data objects рисуйте в редакторе: `bpmn_edit` их не потеряет молча, а откажется и спросит.
- Local API: при вызове инструментов ответ приходит целиком, без стриминга по токенам (ограничение `--json-schema` в CLI).

## Тесты

```bash
npm test
```

Тесты (нужен собранный `dist/site`):
- генерация 7 сценариев (C8/C7) с линтером Modeler, XSD BPMN 2.0, round-trip и DI; правки с сохранением раскладки; пулы и дорожки; Camunda 7 в формате старой панели без потерь;
- правка ассистентом схемы Camunda 7 со всем, что не описывает его модель: initiator, resultVariable, скрипт из ресурса, async и retry у multi-instance, условие из ресурса, standard loop, external-task error, listener на разделённом потоке, delegate у message end event, переименование элемента; `bpmn_write_xml` не затирает правку из редактора;
- хранилище: конфликты версий, 20 одновременных сохранений → ровно одно проходит, undo/redo без потерь, лимиты, имена (в том числе управляющие и bidi-символы);
- инструменты ассистента целиком, как их вызывает браузер: создание, чтение, правки, конфликт с редактором, отмена/возврат, отправка схемы на поддельный сервер, экспорт и импорт .zip;
- Camunda 8: message end event с job worker, catch-all error boundary после правок, FEEL `=` в коллекциях и входах; boundary event внутри подпроцесса и в дорожках; id сообщений из Camunda Modeler сохраняются; имена, отличающиеся только регистром, запрещены; файл без раздела диаграммы раскладывается при импорте;
- zip: UTF-8 имена, имена из Windows (CP866) и без UTF-8-флага, служебные файлы macOS пропускаются, совместимость с системными `zip`/`unzip`, повреждённые архивы, zip-бомбы (запись распаковывается больше заявленного), смещения за пределами файла;
- собранный сайт: все файлы на месте, пути относительные, в клиенте не осталось обращений к серверному API;
- ядро ассистента против поддельных провайдеров (OpenAI-стрим с `tool_calls`, Claude API через настоящий SDK, Custom provider, ошибки, повторы); повтор хода при испорченном JSON аргументов; остановка между вызовами не теряет выполненное; отправка схемы без подтверждения невозможна;
- локальный сервер с поддельным `claude`: токен, Origin, Private Network Access, DNS rebinding, `tool_calls` из `--json-schema`, системный промпт через файл, slash-команды, UTF-8 на границах чанков, 413, 429, проверка конфига.
